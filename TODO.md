## Current Status

**Working:**
- Expression tree with batched evaluation (`Expr!T`)
- `use()` combinator for per-element computation
- Operator overloading (`~`, `==`, etc.)
- Entity definition mixins (`Entity`, `Col`, `BelongsTo`, `HasMany`)
- Plain fields (struct instance fields) as alternative to `Col` mixins for eager fetching
- Plain methods (instance methods) for D-side computed values on fetched entities
- POD types (plain D structs) discovered through plain method return types and plain field types
- Custom `Expr!T` nodes returning POD structs work in map/collection contexts
- Cross-collection access via `broadcast()` — computed fields can query unrelated global tables
- `Table` mixin for Query root entry points
- `ForeignKey!Entity` type for type-safe FK columns
- `@GqlHidden` UDA to hide fields from GraphQL schema
- `@GqlName` UDA to override GraphQL field names (for D keyword conflicts)
- `@GqlDescription` UDA to add field descriptions (rendered as doc comments in SDL)
- `@GqlDeprecated` UDA to mark fields as deprecated (rendered with `@deprecated` directive)
- QueryNode-based SQL planning
- JOINs for belongsTo relationships
- Child queries (CTEs) for hasMany relationships
- Computed fields with SQL push-down (dialect-aware: `||` for PostgreSQL/SQLite, `CONCAT()` for MySQL)
- Computed fields in GraphQL schema (static functions taking `Expr!Entity`)
- Field arguments for computed fields (with defaults, introspected from D function signatures)
- Input types auto-generated from struct arguments (with `Nullable!(Nullable!T)` for three-state fields)
- Data-source agnostic Executor
- MockDB for testing (in-memory data)
- DebugSqlDB for SQL inspection (wraps another fetcher, prints generated SQL)
- PostgresDB using `ae.net.db.psql`
- SQLiteDB using `ae.sys.sqlite3`
- MySQLDB using `ae.net.db.mysql`
- GraphQL schema generation (`generateSchemaSDL!(Schema!Query)`)
- SQL DDL generation (`generateDDL!Query`)
- GraphQL query compilation (`compileQuery`) with:
  - Multiple root fields
  - Field arguments (scalars and input objects)
  - Variables (scalars and input objects)
- Mutations with `CrudMutations` mixin (INSERT/UPDATE/DELETE)
- `Schema!(Query, Mutation)` template for bundling query and mutation types
- Filtering with `FilterPlugin`:
  - Auto-generated filter types for each entity
  - String operators: `equalTo`, `contains`, `startsWith`, `endsWith` (and case-insensitive variants)
  - Numeric operators: `lessThan`, `greaterThan`, `equalTo`, `in`, etc.
  - Logical combinators: `and`, `or`, `not`
  - Relationship filters: `some`, `every`, `none` (to-many) and the target's filter (to-one), nested to any depth, pushed into SQL subqueries on root fields
  - Nullable column filters (`isNull`), `like` patterns
  - PostGraphile connection-filter string operators (`includes`, `startsWith`, `endsWith`, `like`, their `not`/`Insensitive` forms, `equalToInsensitive`), Boolean `in`/`notIn`, array field filters (`<T>ListFilter`: `contains`, `containedBy`, `overlaps`, `anyEqualTo`, `anyNotEqualTo`; PostgreSQL array operators, in memory elsewhere)
  - Unknown input object fields are validation errors (literals and variables)
- Sorting with `SortingPlugin`:
  - `orderBy` argument with `asc`/`desc` direction
  - Nested sorting for HasMany relationships
  - Sorting by nullable (NULL last ascending, first descending) and enum (declaration order) fields, as PostgreSQL orders them, in SQL and in memory
  - Replaceable argument surface (`SortingPluginWith`: `{field, direction}` objects by default, `EnumSortSurface`), over the `sortByFields` mechanism
- Pagination with `PaginationPlugin`:
  - `first`/`after` cursor-based pagination
- Runtime introspection (`__schema`, `__type`, `__typename`)
- Directives: `@skip(if: Boolean!)` and `@include(if: Boolean!)` for conditional field inclusion
- Fragments: named fragments (`...FragmentName`), inline fragments (`... on Type { }` and `... { }`), with type condition matching, directive support, and circular reference detection
- Request context via `context!T(expr)` — computed fields can access request-scoped data (auth, locale, tenant) passed via `EvalContext`
- Computed fields from free functions with `ComputedFieldsPlugin` — `auto f(Expr!Entity e, args...)` declared in any module is attached to `Entity`'s schema type; applied straight after `Schema!`, the filtering, sorting and pagination plugins after it filter and sort on computed fields (in SQL where expressible, in memory otherwise)
- Field overrides with `FieldOverridePlugin` — runtime interception of any field resolution via typed delegates, for feature flags, A/B testing, gradual rollouts, or per-deployment customization
- Error path tracking — field-level error catching with path tracking through nested selections (e.g., `["users", "fullName"]`) and partial result support (`{"data": ..., "errors": [...]}`)
- `GqlResult!T` — per-element result type for expressions that can independently succeed or fail per batch element, with error propagation through D operators, `materializeResult()` transform to convert errors to nullable values, `tryUse()` combinator for automatic exception-to-GqlResult wrapping, and array index tracking in error paths (e.g., `["users", 0, "name"]`) via MapExpr's per-element index storage
- Auto-materialization and null bubbling — fields returning `GqlResult!T` are automatically materialized to `Nullable!T` with proper error paths and array index sources; `GqlResult!T` uses inner type's nullability in the schema (`GqlResult!string` → `String!`); non-null fields that error trigger null bubbling (parent object becomes null per the GraphQL spec)
- Query validation — separate validation phase that runs before compilation and collects ALL errors at once: duplicate operation/fragment names, undefined/unused variables, unknown fields, unknown/missing/duplicate arguments, selection set presence checks (scalar vs object). Throws `ValidationException` (extends `CompilerException`) with full error list and source locations
- Polymorphism — GraphQL union types (`@ImplementedBy!(User, Post) struct SearchResult {}`) and interface types (`@ImplementedBy!(User, Post) struct Node { mixin AbstractField!("id", long); }`). Unions dispatch via inline fragments (`... on User { firstName }`); interfaces expose shared fields directly and member-specific fields via fragments. `unionOf!AbstractType(sources...)` factory for expression trees, `SubsetExpr`/`ConcatArrayExpr` for per-member extraction and merging. SDL generates `union`/`interface` declarations and `implements` clauses on object types. Introspection reports UNION/INTERFACE kinds with `possibleTypes`. Validation checks type conditions against abstract type members.
- Subscriptions — `Schema!(Query, Mutation, Subscription)` third type parameter. `DataSource`/`DataSession` split (singleton from per-request state). `SetupMode { query, listen, respond }` for lifecycle phases. `EventSourceExpr!T` core expression for event-driven data. `SubscriptionExecutor!T` manages event delivery and per-event evaluation. `RdbmsSubscriptionPlugin` auto-generates `<entity>Created`/`Updated`/`Deleted` subscription fields from entities. GraphQL compilation, validation (single root field rule), introspection, and SDL for subscription operations.

## Future Directions
- **Expression deduplication** — Grafast-style peer analysis
- **Plan caching** — Reuse optimized plans for repeated queries
- **Subscription transport** — WebSocket (graphql-ws protocol) and SSE adapters for real-time delivery. Currently the subscription engine produces JSONValue payloads; transport is the thin adapter layer to frame and deliver them.
- **Subscription fan-out** — Deduplicate subscriptions so N clients subscribing to the same field share one listener with fan-out dispatch (currently 1:1)
- **Database event hooks** — SQL wrapper hooks (observe executeInsert/Update/Delete, fire ChangeEvent post-commit) and PostgreSQL LISTEN/NOTIFY for cross-process event detection
